ANALYSIS
------------------------------------------------------------------------------
A mutex is a contract with the operating system. When the lock is
taken, a contending thread is put to sleep and later woken, which
costs a system call and a context switch, microseconds per handoff.
Under heavy contention almost every acquisition is a handoff.

CAS never sleeps. A single LOCK CMPXCHG instruction compares and
swaps the value in one indivisible step; if another core won the
race, the loop simply retries with the fresh value. The cost moves
from the kernel into the cache: the 11,442,414 failed retries
above are cores losing the race for the same cache line.

Contended ratio 2.5x vs uncontended ratio 22.2x. The uncontended
figure includes the Python interpreter overhead on the mutex side,
since the CAS loop is compiled. What contention adds on top is the
mutex's sleep/wake handoffs against CAS's cache-line retries.

CAS is not free: under extreme contention the retry loop burns CPU
while making no progress, and a sleeping mutex can be kinder to the
rest of the system. For a single hot counter, however, an atomic
is the right tool, and it is what AtomicInteger in Java uses.
