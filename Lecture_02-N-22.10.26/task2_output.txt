ANALYSIS
==============================================================================
Serial baseline T(1)      : 22.867 ms
Best measured speedup     : 4.1237x at 12 workers
Amdahl bound at that count: 7.7419x  (P = 0.95)
Gap to that bound         : +3.6182x (below the bound)
Amdahl ceiling, p -> inf  : 20.0000x

Measured speedup EXCEEDS the Amdahl bound at 2, 4 worker(s).
That is not an error in the measurement. Amdahl's Law bounds a
workload whose parallel fraction really is P; here P = 0.95 is an
assumption the task hands down, not a measured property of this
code. A chunked reduction is very close to fully parallel, so its
true P is higher than 0.95 and it can beat a bound computed from
an understated P. Splitting the array also gives each thread a
smaller working set with better cache locality than the single
thread streaming all 152.59 MiB on its own.

Measured speedup falls SHORT of the bound at 12, 24 worker(s):
  1. Summation is memory-bandwidth-bound, not compute-bound. Each
     element is read once with almost no arithmetic per byte, so
     the cores saturate the memory controller long before they run
     out of work. That is a roofline limit Amdahl does not model.
  2. Thread pool dispatch and the final reduction over the partial
     sums are serial overhead that grows with the worker count.
  3. Past 12 workers the pool oversubscribes the 12 logical
     cores, so the extra threads only add scheduling cost.
