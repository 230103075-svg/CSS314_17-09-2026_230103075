ANALYSIS
==============================================================================
Path A moves data by rewriting it. pickle walks the array and
produces a byte stream, the operating system copies that stream
through a pipe, and the child allocates a fresh array and fills it.
The payload is touched at least three times and exists twice in RAM
at the peak. The cost therefore grows with N, and grows steeply:
at N = 100,000 path A takes 3.131 ms, at N = 10,000,000 it takes 297.366 ms.

Path B moves nothing. The region is mapped into both address
spaces, so the child reads the very same physical pages the parent
wrote. What travels through the queue is the name of the region, a
handful of bytes, and that is true at every N. Hence B2 is roughly
flat: 0.191 ms at N = 100,000 against 0.369 ms at N = 10,000,000.

B1 sits between them. It still performs one memcpy into the shared
block, so it scales with N, but a single memcpy is far cheaper than
serialise-pipe-deserialise. B1 is the number to quote when the
producer hands over an ordinary array; B2 is what a real pipeline
achieves by allocating into shared memory in the first place and
never making the copy at all.

At the largest size, shared memory is 32.9x faster including the copy
and 806x faster without it.

This is the same lesson as the GPU branch of the task. There the
bottleneck is the PCIe bus and the remedy is to keep data resident
on the device across several kernels instead of copying it back and
forth. Here the boundary is between processes and the remedy is to
keep data in a shared mapping instead of serialising it. In both
cases the arithmetic is not the problem: moving the bytes is.
